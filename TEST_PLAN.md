# План тестирования

## Цели тестирования
Проверка соответствия приложения всем требованиям технического задания.

## Тестовые сценарии

### Сценарий 1: Штатное завершение
**Параметры:**
- Ячеек: 20
- Слотов зарядки: 4
- Автоотмена: выключена

**Команда запуска:**
```bash
dotnet run -- -b 20 -s 4 -d 100000
```

**Ожидаемый результат:**
- Все ячейки получили статус Completed
- Количество Completed = 20
- Количество Canceled = 0
- Количество Faulted = 0
- Приложение завершается самостоятельно

**Проверяемые требования:**
- ✅ Корректное использование ThreadPool
- ✅ Ограничение SemaphoreSlim (максимум 4 одновременно заряжающихся ячейки)
- ✅ Защита Mutex (только одна ячейка калибруется в любой момент)
- ✅ Потокобезопасность операций
- ✅ Корректное журналирование

### Сценарий 2: Отмена во время зарядки
**Параметры:**
- Ячеек: 30
- Слотов зарядки: 3
- Автоотмена: 2000 мс

**Команда запуска:**
```bash
dotnet run -- -b 30 -s 3 -t 2000
```

**Ожидаемый результат:**
- Часть ячеек завершилась успешно (Completed)
- Часть ячеек получила статус Canceled
- Приложение корректно остановилось
- Нет зависших ожиданий
- Все ресурсы освобождены (SemaphoreSlim, Mutex)

**Проверяемые требования:**
- ✅ Обработка CancellationToken
- ✅ Прерывание ожидания SemaphoreSlim при отмене
- ✅ Освобождение ресурсов при отмене
- ✅ Корректное завершение работы после отмены

### Сценарий 3: Отмена во время ожидания калибровочного стенда
**Параметры:**
- Ячеек: 40
- Слотов зарядки: 6
- Автоотмена: 3000 мс

**Команда запуска:**
```bash
dotnet run -- -b 40 -s 6 -t 3000
```

**Ожидаемый результат:**
- Часть ячеек отменилась во время ожидания Mutex
- Мьютекс не остался занятым
- После завершения повторный запуск выполняется без ошибок

**Проверяемые требования:**
- ✅ Ожидание Mutex с возможностью отмены (WaitHandle.WaitAny)
- ✅ Гарантированное освобождение Mutex
- ✅ Отсутствие утечек ресурсов

### Сценарий 4: Быстрое тестирование
**Параметры:**
- Ячеек: 5
- Слотов зарядки: 2
- Диагностика: 10000 итераций

**Команда запуска:**
```bash
dotnet run -- -b 5 -s 2 -d 10000
```

**Цель:**
- Быстрая проверка базовой функциональности
- Визуальная проверка журналирования
- Проверка порядка освобождения ресурсов

### Сценарий 5: Ручное прерывание (Ctrl+C)
**Параметры:**
- Ячеек: 25
- Слотов зарядки: 5
- Автоотмена: выключена

**Действия:**
1. Запустить приложение
2. Подождать 2-3 секунды
3. Нажать Ctrl+C

**Команда запуска:**
```bash
dotnet run -- -b 25 -s 5
```

**Ожидаемый результат:**
- Приложение перехватывает Ctrl+C
- Запускается процесс отмены
- Ячейки переводятся в статус Canceled
- Ресурсы корректно освобождаются
- Выводится итоговая статистика

## Метрики проверки

### Критерии приемки из ТЗ:
1. **✅ Приложение компилируется и запускается на .NET 8.0**
2. **✅ Все ячейки обрабатываются в пуле потоков**
3. **✅ Количество одновременно заряжающихся ячеек не превышает заданное число слотов**
4. **✅ Калибровка выполняется только одной ячейкой в любой момент времени**
5. **✅ Отмена по Ctrl+C или по таймауту приводит к корректной остановке**
6. **✅ После отмены приложение не зависает**
7. **✅ Все занятые SemaphoreSlim и Mutex освобождаются**
8. **✅ Итоговая сумма статусов равна количеству ячеек**
9. **✅ Журнал позволяет убедиться, что этапы выполняются и ресурсы освобождаются**
10. **✅ Повторный запуск приложения после предыдущего запуска работает без ошибок блокировки ресурсов**

### Дополнительные проверки:
- Потокобезопасность общих структур данных
- Корректность временных меток в журнале
- Отсутствие deadlock и race conditions
- Производительность и масштабируемость
- Читаемость и понятность вывода

## Инструменты тестирования

### Автоматизированные проверки:
1. **Компиляция:** `dotnet build`
2. **Запуск с разными параметрами:** как указано выше
3. **Проверка вывода:** анализ журнала и статистики
4. **Проверка потоков:** мониторинг использования ThreadPool

### Ручные проверки:
1. Наблюдение за порядком выполнения операций
2. Проверка корректности прерываний
3. Валидация итоговой статистики
4. Проверка обработки ошибок

## Ожидаемые результаты тестирования

### Успешные тесты должны показать:
1. Стабильную работу приложения при разных нагрузках
2. Корректное освобождение всех ресурсов
3. Правильную обработку отмены операций
4. Отсутствие утечек памяти и ресурсов
5. Понятный и информативный журнал работы

### Обработка пограничных случаев:
1. Минимальная партия (1 ячейка)
2. Максимальная нагрузка (100+ ячеек)
3. Минимальное количество слотов зарядки (1)
4. Нулевое время автоотмены (мгновенная отмена)
5. Большое количество диагностических итераций
